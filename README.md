# 地铁跑酷 · 浏览器重建试玩

从用户手机上的 `com.kiloo.subwaysurf` 7.07.0 APK 恢复角色、蒙皮、动画和环境资源，并用 Three.js 实现浏览器跑酷交互。经典路线已接入完整的 49 个命名路段及原版章节配置；完整 Android 客户端及其他模式尚未移植。

## 本机启动

```sh
npm ci
npm run dev
```

打开终端打印的本机地址。`npm test` 验证移动、碰撞、金币、暂停、车顶等行为；`npm run build` 生成 `dist/`。

## 操作与角色

- 方向键 / WASD：左右换道、向上跳跃、向下翻滚；空格也可跳跃。
- P / Esc：暂停或继续；触屏可上下左右滑动。
- E / 双击画面：启动普通滑板；本地试玩每局提供 3 块，撞击消耗保护。
- 失败后可在 8 秒内选择「试玩复活」；本地每局一次，保留已跑距离、金币与积分。
- 「导入角色」读取本机 GLB，在浏览器内替换外观；文件不上传至游戏服务器。
- GLB 自带的动画会按名称匹配 run / jump / roll。没有骨骼或动画的模型只能显示静态外观，需要完成绑骨和动作适配后才能获得对应动作。
- 默认玩家角色为 Hi3D 黄色小怪兽，刷新后恢复该角色，无需手动导入。
- 当前追逐者为新的 Hi3D 红鼻子长耳角色，单个角色替代原来的警卫与狗组合。追逐、绊倒、抓捕和复活判定继续使用已有经典模式规则。
- 黄色角色使用完整全身模型；26 根骨骼层级和跑步 / 跳跃 / 翻滚曲线来自已恢复的 Jake 资源，按黄色角色体型重新确定关节位置、蒙皮权重及休息姿态对齐。短腿接地经过适配，不等于原版角色的逐顶点动作。
- 翻滚全程保持角色尺寸，不再缩放骨骼。原版已在翻滚时忽略重复下滑，约 0.542 秒到原动画终点后才接受下一次。循环首尾姿态仍保持连续，新的有效输入会重新播放，不缩放、不因反复输入钳在最后一帧。
- 游戏版模型约 9.89 MB、77,944 个三角形，包含 44 条原版动作来源并保留原贴图。黄色角色已切开两侧腋下的粘连带、保留连续肩部并重建内侧曲面；手臂和腹部按真实网格连通性分配权重，内侧手指也归入各自手臂。肩部使用连续权重过渡，腹部不受手臂骨骼拉动。短胖体型的动作幅度和接地仍有适配。

角色来源、骨骼映射及动作出处见 `public/assets/character/yellow-runner.json`；本机上级 `tools/character-pipeline/repair-yellow-arms.py` 从归档模型完成腋下拓扑修复，再由 `build-yellow.mjs` 生成蒙皮及原版来源动作。下载的 Hi3D 原模型保留；修复输入、方法、形变扫描和验证记录位于上级 `analysis/character/yellow-arm-repair/`。`scripts/character-preview.html` 是仅用于本地检查的动作预览页，不进入正式构建。

红鼻子追逐者来自 Hi3D 任务 `37e98af3991e4cacb6817b0fd75413cb`，游戏版本约 4.05 MB、74,992 个三角形，保留双脚、双耳、红鼻子和完整尾巴；原始 45.9 MB 文件未覆盖。模型重新绑定 18 根警卫来源骨骼，并适配 12 条原版警卫动作，尾巴跟随骨盆、耳朵跟随头部。短臂与背部动作幅度、体型和接地经过显示适配，融合部位仍可能有局部形变。追逐场景只实例化这个角色，原警卫与狗不再加载蒙皮/动画。来源与转换记录见 `public/assets/character/red-nose-chaser.json`，本机生成脚本为上级 `tools/character-pipeline/build-red-chaser.mjs`；`scripts/chaser-preview.html` 用于本地动作检查。

## 资源与实现

`public/assets/recovered/manifest.json` 保留提取资源的来源引用与限制说明。Jake 使用真实网格、26 根蒙皮骨骼、绑定矩阵和跑步 / 翻滚 / 跳跃曲线；动画按 Unity 曲线切线采样。列车、障碍、金币、双铁轨及城市建筑来自 APK 中可追溯的资源。

`src/config.js` 分别记录原生代码已证实的默认值与浏览器调校值。网页版采用每 10 个 Unity 世界单位对应 1 个显示单位的比例；原生构造器默认值可能被序列化数据或 XLua 热更新覆盖，不能视为手机运行时实测值。相机、着色器、音频播放与事件对时、物理接触检测仍有浏览器实现和调校。

`src/route-generator.js` 执行原始层级、章节和随机选择；`src/environment-layout.js` 处理环境类型、强制区间及模型拼接；`src/game-core.js` 为独立于渲染帧率的模拟；`src/asset-adapter.js` 负责 Unity 提取资源和 GLB 适配；`src/main.js` 负责场景与交互。资源更新后可从此目录执行：

```sh
node scripts/sync-assets.mjs
```

该脚本合并本项目上级的基础资源以及 powerups、flight、classic、classic audio-v2、presentation-v3 以及 intro/effects/audio/revive-v4 资源补丁，并重算公开资源校验和。单独取得网页仓库时，已有的 `public/` 资源足以运行，不必重新提取 APK。

测试覆盖全部 49 个路段的 16 个种子、完整资源引用、半随机抽取与章节约束、真实斜坡及移动列车碰撞，并验证长序列环境生成。所有验证针对已恢复的原生回退逻辑；不会证明 XLua 热更新与手机运行时完全一致。

## 经典碰撞、追逐与复活

- 外侧越界与列车侧碰触发绊倒；侧碰按当前换道距离回弹。首次绊倒的易被抓窗口为 5 秒，期间再次绊倒启动约 0.2 秒的死亡请求；滑板可吸收致命结果，飞行在提交死亡时再次检查。
- 警卫追近采用源 0.7 秒平滑曲线，从 30 接近至 10 Unity 单位，恢复后在 1.5 秒内退回。1 秒内再接触不同实体的源连续碰撞分支也已接入。
- 219 个碰撞体带有 APK 中的真实标签和层。只有实际 Hit 层触发器走非实体碰撞分支；不能仅凭 Stumble 标签忽略实体碰撞。
- 黄色角色增加 11 条经典受击/被抓动作。原版 MexicoCity 警卫和狗的真实蒙皮、绑定矩阵、贴图和动作保留在来源资源中；导出时独立纠正压缩权重解码，并验证休息姿态误差。其网格绑定在动画根坐标，不能重复应用原 Renderer 所在骨节点变换。当前实际显示已替换为上述红鼻子追逐者。
- 复活保持同局距离、金币、积分、路线、横向位置。按源约 0.144 秒延迟、250 Unity 单位乘速度归一化的范围清障，以及 15 Unity 单位跳高恢复跑动。复活弹窗期间道具与速度增长计时继续；暂停冻结这些计时。一次免费复活与三块滑板是本地试玩配置，不是恢复的玩家账户库存。

证据分别位于上级 `analysis/classic/collision/collision-findings.json`、`analysis/classic/revive/findings.json`、`analysis/classic/resources/`。`scripts/classic-preview.html` 是不会进入正式构建的定向回归页。

第二轮经典还原已用原生 ObstacleImpactUtil 的 X/Y/Z 分类替换近似接触面分类。保护区中的 double `0.33` 和 float `0.33000001311302185` 已按包内 AES 路径恢复；小障碍的 0.8 单位弹起、HitBounceOnly 前角双通知、顶头穿行条件和移动列车特殊分支都有独立来源。碰撞使用原 CharacterTrigger 胶囊参数，不再拿 1.95 单位高的角色外观代替碰撞体：站立半径 .3、中心 Y .55、高 1、前偏 .1；滚动写入高 .4/中心 Y .4，浏览器按直径最小高度 .6 处理。接触宽相、表面检测、斜坡接缝、胶囊最小高度与固定帧事件顺序仍是明确的物理适配。

普通换道使用 `3 / 当前显示速度` 秒并按剩余车道距离缩放。离开平台后、尚未进入主动跳跃且下落速度大于 -3 时可以起跳；下降中提前请求跳跃会在落地执行，翻滚清除该请求。普通下翻速度为 `-sqrt(2 * JumpHeight * gravity)`；背包结束时源高度 70–125 Unity 单位的 Running.Begin 过渡已接入，过渡期间下翻采用 -250 Unity 单位/秒。超过路线相对高差 200 的特殊重复 Roll 包装层仍未完整接通。

默认跑步、跳跃、滞空和落地池保留顺序及重复权重。新增真实左右闪躲、落地与随机跳跃变体，跑步/换道动画按 `speed / 11` 调速；落地按源速度阈值选角色，默认三个落地等级共用同一池。翻滚以原 clip-length deadline 为上限，同时把 Three.js 动作 enabled 状态与本次 roll token 反馈给固定步模拟，支持被淡出打断时提前结束。多动作连续打断保留当前权重，不把旧翻滚重新抬到满权重；具体渲染帧与 Unity legacy Animation 调度仍有适配差异。

普通抓捕按车道相对 X 和原配对池选择两人的动作；追逐者立即播放，玩家动作从零时刻开始但先隐藏权重，按原 offset/25（.68 或 .96 秒）等待后用 .2 秒淡入。抓捕回调等待序列化的 3 秒后才显示完整 8 秒复活选项。红鼻子角色采用独立跳跃重力、距离/速度延迟，跟随最后着地高度而非直接复制玩家跳高。体型、融合网格蒙皮和抓取接触点仍做显示适配，不能视作原两人模型逐顶点一致。追逐者恢复后按源 3 秒延时隐藏，死亡阻止当次隐藏；复活重置并隐藏。移动列车演出先用 .5 秒移向受击时镜头位置的下方；仅在源 ShowEnemies 为真时，接入 .6 秒后开始的 1 秒下沉段。移动列车同样保留默认 3 秒展示等待；源等落地/超时与额外弹窗队列还未逐条复制。

原 APK 的 27 个独立音频与 33 个用途绑定已导出，包含 MexicoCity 主题音乐。现有音效开关默认关闭，开启后播放原主题、换道/跳滚/落地/受击/道具音效，磁铁与背包循环会随状态退出。17 条普通玩家动画上的 58 个事件已按原帧号注册，包括跑步脚步、跳跃/跑鞋跳跃、翻滚、落地、受击和喷漆/摇罐；使用实际动作时间、循环计数及权重触发。滑板动画事件仍保留原浏览器事件适配。金币声由 CharacterPickupParticles.CoinPickup 的明确引用补齐。音频文件有原对象、压缩资源、PCM 与公开文件哈希。声音音量与浏览器事件触发时刻是适配。

本轮证据位于上级 `analysis/classic/collision-v2/impact-findings.json`、`analysis/classic/locomotion-v2/findings.json`、`analysis/classic/motion-v2/findings.json`、`analysis/classic/audio-v2/patch-validation.json`。恢复后的常量另写派生文件，原 ELF/APK 未改动。原生 disableForward 的 CanAccelerateForward 消费路径、弹跳鞋与顶头的细分裁剪仍需闭环；并未猜测将其等同立即减速。掉入缺口后的复活仍恢复到清空后的地面，原生死亡瞬间最低速度写入尚未模拟。

## 第三轮：开场、特效与相机

普通开场使用原 `idlePaint`、`introRun`、`guardIntro` 和 `startPan` 曲线。等玩家源动作约 1.208333 秒后进入跑步并开放操作，期间跑跳换道不排队；暂停同时冻结开场计时。初始追逐者在原生距离 10，5 秒危险期从开场即开始，结束后用 1.5 秒退回 30。黄色模型保留 26 根骨骼并增加菜单/开场动作；菜单长动作按 Hermite 60 Hz 采样，其他动作 120 Hz。Hi3D 朝向适配导致的开场根 X 翻转已纠正，Z 仍按 Unity→Three 坐标转换。

原 `Intro_environment` 静态场景按当前主题和真实 placeholder 绑定展开，包含起跑列车、货车、轨道、信号灯和喷罐/包等物件；源轨道脚下面约 y=0。静态物件随已跑距离滚到身后。两个需要运行时选择的灯光 provider 未猜测同时启用；第四轮已接通喷漆与喷罐动作事件；未在已核对原生路径中找到独立的背包转移动作，因此保留源静态布置。眼睛启停通知已恢复，但黄色模型没有对应眼部骨骼，其他主题选择仍未补齐。

相机替换了旧的手调跟随：跑步横向 .75、原目标与位置偏移、SmoothDamp、.5 秒高度/pitch接续，保留普通跳跃与真实着地高度的区别、跑鞋跟高、普通背包起飞曲线/巡航横向 .9、原屏幕比例 FOV、致命撞击 Shake。相机菜单子节点必须先应用 `SetMenuCamera` 的位置与俯仰，再采样父级动画；不能只读场景作者的静态 TRS。只依据源 Subway tag 触发区域进入/离开来限制镜头高度，飞行高于上限时执行 ForceLeave；没有根据隧道模型名称猜区域。Tunnel CameraModifier 自动切线和 Headstart/FOVGip 等特殊分支未接到当前普通模式。

原拾取闪光网格、材质贴图和缩放曲线已接金币/道具事件；金币效果 .201 秒，道具 .28 秒，亮度按源白→黑变化。补上真实金币音频、滑板碰撞粒子、绊倒星星/树叶、落地翻滚尘石、滑板落地火花、喷气背包双侧网格尾流及其原 -2 UV 滚动速度。粒子桥使用源发射/寿命/形状/速度/重力/颜色/缩放等模块与原 PNG/mesh，每发射器最多 256 粒子，暂停冻结、重开清空。第四轮按实际 shader 身份恢复特效的混合、剔除、深度、颜色公式和源 Gamma 空间；启用的 NoiseModule 使用可重现的噪声近似。全场景 distortion/fog、软粒子深度、视口尺寸限制及排序仍有差异；已审计的 Trail/UV 动画模块在源中关闭，未额外添加。身体附着位置与事件调度仍有明确显示适配。跳起扬尘的 Play 通知未恢复，只恢复了 .5 秒后 Stop；浏览器在跳起开始发射，不能将此时机说成完整源逻辑。

`src/classic-intro.js`、`classic-camera.js`、`classic-camera-volumes.js`、`source-camera-rig.js`、`classic-effects.js`、`source-particles.js` 各负责独立的时序、镜头、区域、动画采样、特效事件与粒子仿真。`scripts/presentation-preview.html` 为本地可见按钮驱动的定格回归页，隔离随机障碍且不进入正式构建。对应原生/资源证据在上级 `analysis/classic/intro-v3/`、`camera-v3/`、`effects-v3/`、`presentation-v3/resources/`。原 APK/ELF 与下载的 Hi3D 原模型未修改。

## 第四轮：开场细节、特殊效果和动作衔接

菜单喷漆按照 `idlePaint` 的 24 fps 事件执行七段启停；三个真实喷漆粒子系统与喷罐同挂在右手骨骼，保留源局部变换，只施加一次坐标转换和黄色角色体型系数。停止喷漆后已有粒子自然消散，进入开场时隐藏喷罐并清理菜单粒子。眼部事件有记录，但不会给没有对应骨骼的 Hi3D 模型伪造源眼部动画。

复活点击接受时先播放原镜头粒子，经过约 .144 秒后恢复跑步、重置追逐者并显示原 `powRevive` 护盾。护盾挂在 Character 物理根，保留原网格、材质及默认 `Shield` 四元数曲线；1.5 秒时停止动画采样但继续显示，2 秒时清理。原 `ReviveAnimationClip` 仅用作计时引用，未把它的缩放/颜色曲线错误应用到 `Animation.Play()` 的另一默认 clip。暂停冻结护盾，重开清理；这段视觉时长不表示额外新增 2 秒无敌。

动作事件按接收先后决定衔接，保留发生换道时的地面/空中上下文；落地不覆盖正在进行的翻滚，连续滚动→换道→跳跃不会重新激活残余旧动作。脚步和喷罐声音按实际播放时间触发，暂停、循环、重开和重新激活动作分别处理。相机延用上一轮恢复出的菜单/开场、跑步、跑鞋、车顶、隧道和背包路径；本轮列车受击使用受击前的镜头位置，避免每帧追逐抖动镜头。

新增证据位于上级 `analysis/classic/intro-v4/`、`motion-v4/`、`effects-v4/`、`audio-v4/`、`revive-v4/`；公开资源继续保留源对象引用和文件校验和。特效噪声、粒子预热/排序、整个 Unity 场景的着色、特殊镜头分支、XLua 热更新以及手机逐帧对照仍未完成；不能把本轮重建称为原版逐帧等价。

## 黄色角色腋下拓扑修复

使用闭合的圆滑切割体移除前臂与腹部之间的融合网格，保留源肩部的连续表面和原有 UV；新露出的内侧表面使用相邻皮肤颜色。修复后的上身在几何焊接检查中无开放边，两侧手掌都通过连续肩部连接到躯干。原来按横坐标切分权重会误把内侧手指归给腹部，现改为根据肩部以下的表面连通区域标记手臂/躯干，再在肩部平滑混合。
